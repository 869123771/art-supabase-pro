# 菜单主列表列配置

## 入口与权限

- 菜单：系统管理 → 列配置，路由和视图均为 `/system/column-config`。
- 使用现有 `BusinessMenuFilter`、`ArtWorkspaceSplitter`、Art 表格和状态组件。
- 维护权限：`System:ColumnConfig:Manage`；目录同步权限：`System:ColumnConfig:Sync`。
- UI 和数据库均校验平台超级管理员能力。普通用户可读取自己的有效方案，不能保存方案、切换表格来源或同步目录。
- 平台配置是跨租户控制面；租户、角色、用户方案由平台超级管理员指定目标。角色和用户必须属于目标租户，普通请求中的伪造租户头不生效。

## 数据归属

| 数据表 | 责任 |
| --- | --- |
| `sys_table_column_catalog` | 菜单主列表列目录、源文件和版本 |
| `sys_table_column_profile` | 平台、租户、角色和用户方案 |

所有表启用 RLS，认证角色没有直接写表权限。公开 RPC 使用 SECURITY INVOKER；需要受控授权的实现位于未暴露的 `app_private`，显式校验当前身份，撤销匿名执行权限。

保存采用预期版本检查和事务锁，防止两个管理员相互覆盖。结构列、必要操作列、未登记字段、跨租户对象和无效宽度均由数据库检查。没有新增业务数据删除流程。

## 生效规则

1. 每个菜单的主列表独立选择「前端定义 / 读取配置」，同一张表的全部列统一来源，不存在逐列来源或页面级总开关。未配置的表格默认使用前端定义；其运行时响应只返回模式，不传输列目录。
2. 开启后按平台 → 租户 → 角色 → 用户覆盖。角色优先级从低到高，相同时按方案 UUID 固定排序。
3. 每层支持继承来源、前端定义、配置驱动。配置列只能覆盖原始列集合中的展示属性。
4. 原始格式化函数、字典、跳转、按钮权限及字段权限继续由业务代码和服务端负责，数据库不保存可执行代码。
5. 配置不增加原始工厂未提供的列，支持当前页排序，已接入服务端排序的列保留原有 custom 规则，保留操作列和权限收紧。列显隐不会自动裁剪接口数据。
6. 配置读取失败回退到前端列并给出可重试反馈；缓存按用户、租户范围、菜单和本地版本隔离。缓存有效期 60 秒，重新激活页面时按需刷新，保存当前表格方案后会立即清除当前页面会话缓存。

`useTableColumns` 覆盖常见内管和外管列表；`ArtTable` 负责直接传入列及模板插槽列。根据原始列标识匹配主列表目录，排除不匹配的内嵌表和弹窗/抽屉内表格。模板插槽保留原 VNode、单元格和交互。

## 页面交互

- 页面使用项目的 `--art-full-height` 可用高度，左侧菜单树和右侧表格独立滚动；列数增加不会撑长整页。
- 专注模式位于页面右上角；进入后在工作区右上角保留退出入口，Esc 也可退出，范围、列设置与保存保持可用。
- 前端模式显示只读列信息；切到配置模式后统一开放全部业务列的显隐、拖拽/按钮顺序、标题、列宽/最小列宽、三项固定位置、允许排序、对齐与长文本提示。结构列继续遵守系统保护。
- 列设置和草稿表头预览共用一个工作区，保存操作固定在底部。切菜单、范围或离开路由前保护未保存修改。
- 窄屏通过菜单抽屉选择功能，避免将完整导航树堆叠在表格上方。
- 初版页面级全局控制对象已移除，移除前快照保留在 Git 忽略的备份目录中。

## 当前页列过滤

- 每个业务列可选择不过滤、文本搜索、复选框多选、数值范围、日期区间或日期时间区间。类型与布局方案一起按当前表格、当前配置范围保存；具体过滤条件只保留在当前表格会话中。
- 业务表头使用公共过滤弹层。文本忽略大小写；复选项从当前页原始数据去重生成，可搜索、全选、清空；数值和时间支持单侧范围、包含边界。日期结束值包含当日全部时间，日期时间包含所选秒。
- 支持仅空值、仅非空值。同列多选取或，不同列取且。显示当前页过滤数量、过滤后的行数以及清空入口，不修改服务端分页总数。
- 配置型列、模板插槽列和嵌套字段使用同一过滤工具；树表保留命中子项的祖先。权限隐藏列的条件不参与过滤，切换配置上下文清空条件。
- 过滤值按原字段比较，字典复选项使用字典标签展示；文本搜索匹配原字段值。当前页过滤不能替代业务接口的全量搜索，导出仍沿用业务模块原有的数据范围。
- 当前页存在活动列过滤时禁用行拖拽，避免过滤索引与原始数据索引错位。

## 前端目录同步

生成入口：`scripts/generate-table-column-catalog.ts`。通过 TypeScript AST 和 Vue 模板静态提取元数据，跟踪实际渲染的共用工作区和模块别名；不执行业务函数。生成文件：`src/config/table-column-catalog.generated.json`，禁止手工修改。

更新流程：

1. 通过项目 Supabase MCP 读取当前 `sys_menu`，将 JSON 保存到 Git 忽略的 `.artifacts/column-config/menu-backup.json`；也可将自选输入文件作为脚本第一个参数。
2. 执行 `pnpm exec tsx scripts/generate-table-column-catalog.ts <菜单JSON文件>`。
3. 核对 `.artifacts/column-config/inventory.json`，区分详情、图表、非本地入口和需要适配的新列表；不能将未登记菜单视作已接入。
4. 超级管理员在列配置页面执行“同步前端列目录”。同步更新公共目录，保留已有方案。已保存方案出现新列时按前端默认补入；停用的列不会在运行时凭空出现。

2026-10-23 首次导入：398 个菜单主列表、5,118 个列定义；其余菜单仍显示在左侧树中，未登记列表显示明确空态。目录同步不自动开启业务表格的配置模式；各菜单、各范围保存的方案独立生效。

当前代码目录已复核为 400 个主列表、5,208 列：补齐招聘工作台的六种列集合、报工台账及保险分组子列，排除仅存在于弹窗/抽屉的附表。详情关联表与 SQL 任意结果集不属于菜单主列表目录。

最终按实时菜单重新生成并同步 19 项新增或变化的目录；400 个有效菜单的 ID、路径、版本与远端逐一一致。数据库保留 2 项旧附表目录，合计 402 行；旧记录不进入当前路由索引和配置管理列表，不删除可能需要恢复的历史方案。列配置编辑器本身不登记为业务主列表。

生成脚本同时维护轻量路由索引 `src/config/table-column-routes.generated.json`。运行时仅为索引内的菜单请求配置；管理页忽略已不属于当前前端目录的旧目录记录，保留其数据库方案以便恢复。多标签动态列表按各自列集合匹配，分组子列在原分组内调整，不能借配置跨分组移动或凭空增加字段。

回退时将目标菜单的表格来源设为「前端定义」并保存；只影响当前表格，其他表格的方案保持各自状态。若撤销整项交付，只移除本次新增的菜单授权、菜单、RPC 与配置对象，恢复前端改动；不要删除任何业务历史。
