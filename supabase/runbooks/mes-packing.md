# MES 排包交付记录（2026-09-20）

目标 Supabase 项目：`ckbftoopuyophiebamwy`。数据库结构、权限、菜单和 RPC 经事务回滚演练后由 Supabase MCP 直接应用；本仓库不保存迁移 SQL。

## 数据关系与口径

- `mes_work_order_detail` 是板材区域、编号、长宽、块数、面积的唯一来源。包装参数 `axis`、`thickness_mm`、`unit_weight_kg` 补充在同一明细行；`packed_pieces` 由排包保存事务汇总回写。
- `mes_pack_rule` 按租户和成品类型唯一，已为有维护权限的租户配置岩棉板、聚氨酯板两套初始规则。自动排包只是建议；人工调整包在保留模式下不被重新计算覆盖。
- `mes_work_order_pack` 为包号主表，租户内包号唯一。`mes_work_order_pack_item` 按工单明细 ID 与块数分配，可将同一明细行拆入多个包，且外键校验租户一致。工单明细有包内引用时不能被删除。
- 现有生产工单编辑会全量重建明细，因此已排包工单的明细修改会被外键保护拦截。业务上先在排包单拆包并保存，再修改工单明细和重新排包；页面提示了该顺序。
- `mes_save_packing_plan` 锁定工单、校验版本、包号、区域、轴线、块数和板材归属，在一个事务内保存包与明细并回写已排包块数。`mes_save_packing_board_spec` 禁止修改已排包板材的轴线与厚度。
- 三张新增业务表启用 RLS。读取按租户范围与菜单权限过滤；业务修改只由校验登录、按钮权限和租户边界的 RPC 完成。平台超级管理员保留单独的 INSERT、UPDATE、DELETE 策略；客户端没有直接表写入授权。
