# 采购合同与采购申请优化（2026-09-24）

## 范围

- 采购合同、采购申请使用现有编号引擎；默认规则分别为 `CGHT{YYYYMM}-{SEQ:3}` 与 `CGSQ{YYYYMM}-{SEQ:3}`，按月重置，插入时由数据库生成编号。可在系统编号规则中按租户调整规则。
- 采购合同增加字典 `scmPurchaseContractStatus`。草稿、提交、审核后的展示状态随现有审批状态确定。执行中、部分完成、全部完成保留为字典值；采购订单尚未关联采购合同，因此当前不自动判定履约状态。
- 采购合同状态和生效状态由数据库在写入时同步；合同明细增加行号及基本单位；付款计划和条款在前端以表格维护。
- 采购申请增加行号、需求原因、建议供应商、赠品、来源单号和行号；可从销售报价、销售合同及已生效采购合同参选明细。销售报价新增可编辑行号，默认每行递增 10。
- 采购申请列表提供导入、选单与下推采购订单。下推时在订单弹窗中多选申请剩余明细；订单仍使用既有来源数量校验和新增权限。

## 数据边界

- `app_private.guard_scm_purchase_document()` 对赠品行不计入金额、税额和价税合计。
- `app_private.validate_scm_purchase_extensions()` 检查行号、基本单位、建议供应商租户及来源单据与项目、物料的匹配，并同步合同状态。
- 新增采购申请 `Import`、`Push`、`Select` 菜单按钮，角色授权参照原 `Add` 权限；新建采购订单仍需要 `ScmPurchaseOrder:Add`。
- 原采购合同、采购申请记录及相关配置的写前快照位于 `app_private.purchase_contract_backup_20260924`。回退前应先核对快照时间及此后新产生的业务记录，避免覆盖后续业务变更。

## 验证

- 在事务回滚中确认赠品行输入非零单价后，数据库返回的金额、税额、价税合计均为 `0.00`。
- 在事务回滚中确认现有采购合同从 `effective` 转为 `expired` 时，合同状态为 `CNCL`，生效状态为 `expired`。
- 编号规则在事务回滚中分别生成 `CGHT202609-001` 与 `CGSQ202609-001`，未消耗正式序列。
- SCM 模块类型检查、生产构建和浏览器布局检查均通过；浏览器页面数据使用只读模拟响应，不向生产表插入演示单据。
