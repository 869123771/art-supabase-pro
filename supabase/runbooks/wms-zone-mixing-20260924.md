# 库区混放与库存入库校验（2026-09-24）

- 项目：`ckbftoopuyophiebamwy`
- 规则：库区关闭“允许混放物料”后，整个库区内所有有库存的库位只能存放同一种物料；库位自身的混放设置和仓库“一位一品”仍分别生效。定容库位的数量、面积和承重上限继续按库位校验。
- 原因：原校验仅在目标库位检查库区的混放标记，不同物料可分别进入同一库区的两个库位。事务回滚复现结果为 `second_material_allowed`。

## 数据与安全

变更前的 `assert_wms_destination`、`scm_transition_receipt_target_secure` 和 `validate_warehouse_hierarchy` 函数定义保存在 `app_private.codex_backup_wms_zone_mixing_20260924`，已核对备份为 1 行。正式修改先在目标库事务中执行并回滚验证。既有 3 个禁混库区均没有混放库存，演示数据未改写。

`assert_wms_destination` 现在对目标库区加行锁，并检查该库区所有正库存批次的物料。这样两个库位同时入库也使用同一库区锁序列化。检查限定租户和仓库，并使用现有正库存位置索引。收料通知单确认入库也先执行这条目的地规则。`wms_inventory_batch` 的私有触发器保护直接新增、增加库存和增加面积的写入；物料及存放位置不能通过更新批次直接更换，应办理调拨。只减少库存或更新核价、流水时间不重新校验入库容量。

库区改为禁混前，会拒绝已有多种物料的情况；修改库区物料分类前，会拒绝与现有库存分类冲突的情况。带库存的库位不能直接改换仓库或库区；已有库位的库区不能直接改换仓库或租户。新触发函数在 `app_private`，撤销了匿名和认证角色的直接执行权限，原有业务 RPC 的身份、按钮权限和租户校验仍保留。

## 验证与恢复

事务回滚测试证明：同物料跨库位可入库；第二种物料被“该库区不允许混放物料”拦截；已有混放库存时不能关闭混放；带库存库位不能改区。正式应用后再次在回滚事务中验证，同物料允许、不同物料拒绝、超过库位数量上限拒绝。新触发器已启用，收料确认函数包含目的地校验；事务测试产生的库位和批次均为 0 条留存。

Supabase 安全顾问未对新私有触发函数提示可直接调用；收料确认 RPC 的 `SECURITY DEFINER` 可调用提示为原有受权限控制的公开业务入口。性能顾问提示的批次表外键索引及双重读取策略为原有项；新校验复用现有 `wms_inventory_batch_location_idx`，未新增索引。

需要恢复时，先在事务中移除 `wms_inventory_batch_destination_guard` 触发器和 `app_private.validate_wms_batch_destination()`，再从备份表恢复 3 个函数定义并验证原业务路径。确认恢复结果后再正式执行；保留备份直至仓储模块整体验收。
