# 应付款整合：当前实现与验收边界

## 业务边界

采购与运输应付使用 `fms_purchase_payable_document` / `fms_purchase_payable_line` 作为同一个应付单据模型，以 `kind` 区分暂估与财务应付。主表、明细表是同一业务模型的关系型拆分，不再为采购与 TMS 各建一套应付账。运输结算分配仍由原 TMS 结算、收付款关系承载，真实资金余额统一计入 `fms_fund_ledger_entry`；统一应付的核销记录是相关业务事实的同步投影，不再第二次扣减资金。导入应付引用原结算及费用行，不复制付款流水。

菜单迁移保留 `FinancePurchasePayable` 的原菜单标识和已有权限关系，路由调整为 `/fms/accounts-payable/purchase-payable`。暂估页为 `/fms/accounts-payable/estimated-payable`。旧 `/fms/settlement/purchase-payable` 只保留路径规范化，不保留重复菜单或视图。付款条件新增在 `/mdm/financial-master/payment-term`。

界面沿用 Art 的紧凑业务页头、查询表格、专注模式、抽屉、表单及明细选择器。已查询用户标星参考：单据类型（紧凑布局、清晰层次、高效表格）、排包规则和岗位安全责任制；实际布局以本次用户截图和现有组件为准。

## 已接通的流程

- 新增、编辑暂存单据，提交、审核，单据/明细模式分页查询、打印及导出。
- 物料多选、项目参选、库存/基本单位、供应商、部门、税价换算、折扣、赠品清零、来源行追踪。
- 含税单价默认开启、录入金额默认关闭、折扣含税默认开启。数量基准自动计算，金额基准按录入金额拆税；付款计划支持金额/比例切换和总额校验。
- 采购入库下推暂估及财务应付。标准采购不能从暂估直接下推财务，应从同源入库单下推；非入库来源的手工暂估可以下推财务应付。
- 财务保存后保留暂估关联，反映已关联数量和金额；数量及金额基准分别限制已关联上限。
- 审核按原暂估价格生成负数暂估冲回，记录成本差异。部分到票按已审核份额冲回，最后一次吸收尾差，不重估原暂估单价。
- 财务单先建立、同源暂估后审核的情况，在财务审核前重新关联。同一入库行存在多次暂估时分配到各暂估行，财务总额不变。仍有未审核同源暂估时，阻止财务审核并给出处理提示。
- 财务冻结/解冻有原因和金额校验。已导入财务应付的 TMS 结算被冻后，原 TMS 付款申请关联和结算付款反写也不能绕过冻结。
- 凭证预览和生成接入既有自动入账引擎：匹配真实账套、期间、制证规则、科目及辅助核算，不自动猜测科目。缺少配置时返回待配置，不能报生成成功。
- 自动入账规则可选择应付成本口径、成本差异，以及供应商、组织、项目辅助来源；公开查询参选必须持有应付查看权限，不能只凭付款条件权限读取供应商资料。
- 暂估冲回的负数金额在凭证分录中转换为正数反向借贷，适配既有凭证金额非负约束。重复生成沿用原凭证。TMS 财务应付沿用原结算已生成凭证，列表也展示该凭证关系。
- 付款条件维护支持新增、编辑、停用，停用不抹去历史引用。

## 计算约定

金额保留两位，单价保留四位。含税价 = 不含税价 × (1 + 税率)。用户于 2026-10-22 明确确认折后计税口径：先把含税折扣换算为不含税折扣，再按折后净额计算税额，始终保证金额 + 税额 = 价税合计。赠品的三项金额均为零。

付款比例合计为 100% 时，末期金额吸收分币尾差。服务端重新计算比例金额，不信任客户端总数；到期日期须可转换为有效日期。空付款计划可以保存。

成本差异 = 财务成本口径金额 − 被冲回的原暂估成本口径金额；是否含税由两张单据各自的“税额不计入成本”决定。目前差异已记录在冲回明细，不能视为已接通存货成本调整台账。

## 安全与生命周期

公开写入只经受控 RPC，直接向应付主表/明细插入、修改或删除的 authenticated/anon 授权已撤销。公开 RPC 显式认证、精确按钮权限校验、固定空 search_path 和租户范围校验。

- 普通用户使用身份所属租户，伪造 `x-art-tenant-scope` 不改变读写范围。
- 平台超管“全部租户”读取全部，已有记录依其租户写入，新增根记录无显式目标时默认身份所属平台租户。
- 平台超管选定具体租户后仅处理该范围。
- 物料、项目、单位、供应商、付款条件及部门引用校验归属；采购来源的物料不能被替换。
- JSON 中的主数据标识通过存储生成列建立复合租户外键，配套引用索引；主数据引用检查展示应付单号、状态及明细，不允许删除后留下孤立记录。物料编码、描述、规格、项目编码和单位名称由服务端主数据补全，而不是信任客户端只读字段。
- 使用版本号阻止过期编辑；已提交、已审核、系统冲回单不允许编辑或删除。
- 删除必须先经 `MasterDataDeleteGuard` 检查，再确认；关联财务应付、冲回记录或状态限制阻止删除，服务端并发拒绝后重新检查引用。
- 审核、冲回、冻结、保存、删除及制证写入 `fms_payable_action` 审计；删除暂存单不删除已有审计。
- 路由入口逐项声明精确按钮权限并传给共享页，权限目录与后台菜单同步，不能仅由共享页动态推导权限名称。

## 付款核销扩展与剩余范围

### 2026-10-22 付款与核销扩展

新增路由：`/fms/accounts-payable/payment-application`、`/fms/accounts-payable/payment`、`/fms/accounts-payable/writeoff`。MDM 财务主数据增加付款用途、结算方式。路由入口逐项声明按钮权限，普通用户经授权后使用同一业务边界。

- `fms_payable_settlement_document` 为付款申请/付款的统一主表，`fms_payable_settlement_line` 为多往来户明细。申请和实际付款不能只用单一应付外键建模；已移除早期空表方案遗留的单源、单账号主表字段。
- `fms_payable_payment_execution` 保留每次真实付款及取消轨迹。确认生成既有资金流水，取消生成反向流水，不删除原执行。取消是账面撤销，不是银行退款指令。未付款单可作废，之后申请可关闭；不能让取消后的已审核付款永久占用申请。
- 财务应付可下推申请/付款；采购合同和订单可下推预付款申请。订单预付款显式参选采购合同时，与该合同共享预算，同时保留订单自身上限；不更改 SCM 采购订单既有的采购申请来源关系。申请下推付款占用转移，不重复计入额度。
- `mdm_payment_purpose`、`mdm_settlement_method` 保存业务类型、核销属性、结算类别及资金用途。已引用的关键核算属性不可直接改变；可停用后新增。供应商银行账号从 `mdm_supplier_bank` 参选，同时保留单据上的实际收款信息。
- 员工、费用项目及采购合同引用校验租户；员工与费用项目经存储生成列及复合租户外键保护。员工显示姓名、工号，不使用账号绑定专用花名册冒充完整业务人员来源。
- 新租户自动获得 17 种应付/付款类型、4 个付款条件、4 个用途、5 个结算方式、2 个核销方案和两项付款编号规则。编号复用既有编号引擎，按月重置三位流水，不以表行数代替编号规则。
- `fms_payable_writeoff_scheme` 保存启用/自动开关、匹配字段及空值策略；`fms_payable_writeoff_record` 单独核减应付和付款未核销余额。同源确认按启用自动方案核销；预付款可手工匹配。需要调整会计科目的记录才分配核销单号。
- 未制证反核销恢复余额并移除核销单号，保留操作历史。已制证记录禁止反核销；待配置事件在反核销后忽略，不能稍后补生成孤立凭证。支付凭证按执行明细生成，避免多往来户共用一个供应商辅助核算。
- 删除预检沿用共享组件的约定：`inspect()` 返回 `true` 表示阻止删除。曾在验收发现调用方把该返回值反用，已修正暂估/财务列表、付款列表及暂存明细三处；并发引用拒绝后重新检查，展示真实业务单号，而不是继续确认或仅弹通用异常。
- TMS 付款沿用承运现金交易、核销分配、资金流水和 `carrier_payment:recorded` 事件，不另生成重复系统付款凭证。旧付款申请占用与新占用合并控制。真实回归发现并修正承运应付仍受供应商非空约束的问题，以及末笔承运分配反核销回到“已确认”时被误判为重新审批的问题；后者只放行嵌套分配触发、余额归零且无有效分配的派生状态恢复，不放开人工审批状态修改。

### 已确认口径与本轮验证

- 用户确认含税折扣沿用折后计税口径：先换算不含税折扣，再计算折后税额。
- 用户确认双方税额均计入成本时沿用含税成本差：财务应付含税成本减去原暂估含税成本；净额相同但税额变化也会产生差异。其他组合按各单据是否计税入成本分别取净额或含税额。该规则已固定在单元测试和外币冲回数据库回归中；记录差异不代表实际存货成本调整已接通。
- 用户确认异币核销沿用双方单据各自记账汇率，差额计入汇兑损益；不得用核销日汇率覆盖原单。当前仅人民币确认链路已交付，异币确认仍明确阻断，不能以该口径确认代表功能已经实现。
- 现金折扣与现金出款分别计量：核销金额等于实付分摊金额加现金折扣金额。核销记录保存两项不可变分摊；多次部分核销最后一次吸收分位尾差，反核销后恢复对应额度。申请付款状态按含折扣的额度判断，但已付款金额保留真实出款金额。

### 跨账套支付和核销控制

用户确认禁止跨账套付款与核销。服务端不是只检查前端参选：

- 付款明细保存时校验已选资金账户与财务应付的账套，跨租户引用另行拒绝；来源应付缺少账套时明确要求补齐核算配置，不以当前默认账套假装历史事实。
- 每次付款执行保存不可变的 `account_set_id`，通过复合租户外键关联账套。确认时根据实际资金流水、账户或明确来源推导账套，禁止同一付款单混入多本账套；失败回滚整次确认，不留下部分资金流水。虚拟付款也保存确认时账套，取消再确认保留既有事实，不随默认账套切换。
- 提交/审核前也检查一张付款单是否混入多个账套；无效提交保留可编辑的暂存状态，用户可先拆分明细，避免到审核后才发现不能付款。确认边界继续保留原子校验，防范审批后数据变化。
- 手工、自动、同源核销均在核销记录插入边界校验双方账套，不能通过跳过页面或替换方案绕过。已被付款引用的资金账户不能改写账套或核算币种，以免改变历史记录含义。
- 自动方案匹配本身也只接受同账套已确认执行，预览不能先承诺一组到执行时才被账套校验拒绝的配对；不存在或停用的方案明确返回 `false`，不返回可被条件判断漏过的 `NULL`。

### 数量基准下的跨单位关联与冲回

- 继续保留真实流水 `amount`、`allocated_amount`、`unallocated_amount`，不篡改已入账金额和历史状态。统一安全投影新增 `principal_amount`、`fee_amount`、`allocatable_amount`：统一付款的本金取该流水对应执行明细，手续费为实付总额与本金之差，可核销余额只减本金中的已分配金额。普通历史收付款没有统一执行时沿用原流水本金；作废流水可核销余额为零，但仍保留原本金和手续费展示。

- 运输流水表显示“可核销”而非把含手续费的账面剩余数当作应付余额；导出分别列出账面余额、本金、手续费和可核销余额。手续费不参与核销，不改变账面流水；仅剩手续费时不显示继续核销。核销前重新读取最新详情并检查租户、权限、字段及有效本金，失败可重试，不使用过期列表数直接打开可操作弹窗。
