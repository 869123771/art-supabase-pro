# MDM 企业级高可用就绪度审查

> 审查日期：2026-09-08
> 范围：`art-supabase-mdm` 前端、业务 API、远端 Supabase 元数据、RLS/授权/索引、测试与发布链路。
> 总体结论：**企业级治理控制面、租户完整性和可靠交付能力已实现并通过远端回滚校验；持久发布及灾备演练证据完成后方可声明生产就绪。**

## 审查证据

- 远端项目 `ckbftoopuyophiebamwy` 现有 49 张 `mdm_*` 实体/配置表，49 张均已启用 RLS。
- 核心新表的 SELECT 采用限制性 `canonical_tenant_read_scope` 与按钮权限策略组合，能保留平台全租户/选定租户/普通租户语义。
- 统一目录通过 `SECURITY DEFINER` RPC 返回非敏感投影，已有服务端分页、来源、状态、资料完整度和租户范围校验。
- BOM 具有设计、送审、生效、变更、归档/作废状态机；生产日历、工作中心与人员有数据库级校验与部分真实回归证据。
- Supabase Security Advisor 对 MDM 的主要警告是可调用的 `SECURITY DEFINER` RPC；这些 RPC 是有意的 API 边界，但仍需按函数保留鉴权、按钮权限、租户解析和最小授权回归。
- Performance Advisor 确认 `mdm_material` 的 12 个复合外键缺少覆盖索引；表当前约 9 行/192 kB，现阶段补索引的锁定和建设成本低。
- 远端从 `20260716093927` 开始的 665 条历史迁移已通过 `supabase migration fetch` 取回，本地现有真实 baseline 与完整历史，可进入空库重建和安全 diff。

## 已执行变更

1. 为目录来源定义增加 `master | relation` 类型，并用单元测试锁定 **24 类独立主档 + 2 类关系/明细** 的口径。
2. 导航显式标识“权威主档”和“关系明细”，总览改为显示独立主档类型数、关联对象数和待完善记录数。
3. 治理域行增加“待完善/关键资料完整”非颜色文本状态，保留键盘导航和窄屏回流。
4. 生成 `20260908010125_mdm_enterprise_safety_and_performance.sql`，撤销 4 张参考表的匿名授权，并补齐 12 个复合外键索引。迁移设置 5 秒锁等待与 60 秒语句超时，遇到忙时会失败退出而非无界阻塞。
5. 建立数据责任人、规则版本、质量问题/SLA/独立复核、通用主数据四眼变更、黄金记录、crosswalk、候选匹配、拆分/合并审计和事务 Outbox。
6. 将 19 条遗留单列关系升级为 tenant-qualified 复合外键，并补齐子表索引；远端存量跨租户违规为 0。
7. 新增治理控制中心，提供四类作业队列和责任人、规则、消费者三类配置入口；按钮与数据库 RPC 同时执行权限控制。
8. 为到期变更和 Outbox 弃锁恢复建立每分钟 `pg_cron` 调度，使用 advisory lock 与 `SKIP LOCKED` 避免重入和阻塞。
9. 固化 [MDM 高可用、灾备与恢复运行手册](./mdm-ha-dr-runbook.md) 及结构安全 SQL 回归测试。

## 建议的实施顺序

1. **恢复发布基线**：先拉取远端 baseline/迁移史，用全新本地库完成 `db reset`，再发布本次安全与索引迁移。
2. **收紧租户完整性**：对 18 个单列 MDM 外键做存量扫描，分批改为复合外键；验证平台全部、平台选定、普通本租户和伪造租户头四种场景。
3. **建治理控制面**：数据责任人→规则版本→问题单/SLA→变更申请/四眼审批→黄金记录合并。
4. **建发布与恢复链路**：事务 outbox、幂等消费、死信重放、数据合同版本，再补 RPO/RTO、PITR 恢复演练、告警和容量压测。

## 企业级验收门槛

- 从空库可重放全部迁移，生成的 schema 与远端 diff 为空。
- 主数据变更具有提交人、审核人、生效时间、前后值、规则版本和不可篡改审计证据。
- 质量问题可分派、计时、升级、处理、复核和重开，指标能追溯到规则与源记录。
- 所有跨表引用在数据库层阻断跨租户关联，所有写 RPC 同时校验登录、租户、按钮权限与状态迁移。
- 发布事件至少一次投递但消费幂等，失败可观测、可重放，不丢失已承诺的主数据版本。
- 用脱敏数据完成容量、并发、故障注入与恢复演练，并形成经业务确认的 RPO/RTO/SLO 证据。
